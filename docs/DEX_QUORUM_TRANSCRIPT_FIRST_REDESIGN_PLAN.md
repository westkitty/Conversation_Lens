## Corrected user-facing product structure
One application, THREE integrated identities:
1. **DEX//QUORUM** — parent brand; transcript/session/evidence/coordination.
2. **Third Ear** — waveform, capture, transcription, enrollment, speaker classification, acoustic editor and diagnostics.
3. **DEX//Aside** — observations, coaching, sources, cue history, optional local Ollama.

The old three-column always-visible proposal is REPLACED by transcript-first two-surface layout, NOT a change to the three modules' functional ownership.

### Active conversation default
- Top narrow header: Quorum identity, Start Listening / Stop, mic state, very compact live waveform, Settings dropdown. Stop always present when active. No auto-start recording.
- Main: QUORUM transcript uses roughly 65-70% width; ASIDE observations 30-35%. Both occupy nearly full usable height, with independent reading/follow-live as appropriate. Latest observation pinned. Primary transcript is tall; stop rendering it as a 205-340 px subpanel.
- Mobile: Transcript and Observations are prominent main views; current cue and Stop remain reachable without hunting. Waveform minimal, not a permanent Third Ear column.
- Do not show permanent dashboards, observatory maps, enrollment forms, lengthy instructional copy, AI parameter boxes, or metrics during normal conversation.
- The optional full expert cockpit may remain discoverable; simple transcript-first is the default, including after relaunch. Do not invisibly discard prior user layout choice when migrating.

### Settings dropdown / focused drawers
- Conversation: goals, language, context, manual speaker, optional note.
- Third Ear / Audio: device/engine, PCM editor, VAD, pre/post-roll, waveform and signal history, speaker confidence and queues.
- Speakers: profiles, provisional identities, two-sample enrollment, lock/boost, Mixed/Unknown, removal and forget all.
- Aside / Coaching: pause suggestions, grounded evidence, local cue rules, explicit AI opt-in, Big Mac model and tuning, latest and historical cues.
- Review / Evidence: provenance, exact quotes, raw cosine/margin where actually present, corrections, action/decision history, bookmarks, voice-note controls.
- Session / Data: copy/export, snapshots, restore, transcript clearing vs individual/all profiles vs erase session, destructive confirmations.
- Diagnostics / Advanced: health/recovery, observatory, signal stratigraphy, timing, queues, model troubleshooting, performance, keyboard shortcuts.
- Prefer semantic native details, accessible menus/dialogs and existing live handlers. Moving controls must NOT sever event listeners, DOM IDs, capture state, or keyboard paths.
